🛠️ Local Development Workflow

As a developer, use the following commands to edit, test, and preview changes locally before publishing:

1. Run live development server with Hot Module Replacement (HMR):

cd /Users/ravikuruganthy/myApps/website && npm run dev
Runs on http://localhost:5173 (Vite default). Updates instantly as you edit src/ files.

2. Serve built static outputs locally to verify paths before deployment:

cd /Users/ravikuruganthy/myApps/viztral && npx serve
Runs on http://localhost:3000. Used to double-check that relative URLs and built chunks load perfectly.

🚀 Step-by-Step Deployment Protocol

1
Compile Source Code (Build Project)

Switch to the website source repository and execute the production compiler. This outputs optimized HTML, CSS chunks, and JS bundle into the dist/ folder.

cd /Users/ravikuruganthy/myApps/website && npm run build
2
Synchronize Compiled Files to Deployment Mirror

Copy all compiled assets (HTML, CSS, JS, images, logos) from the build directory into your static distribution folder (`viztral`). This replaces the outdated production files.

cp -R /Users/ravikuruganthy/myApps/website/dist/* /Users/ravikuruganthy/myApps/viztral/
3
Commit & Push (Publishing Live)

Navigate to the viztral folder, commit the synced assets, and push to GitHub. Pushing to the main branch will trigger GitHub Pages to serve the updated site on viztral.ai.

cd /Users/ravikuruganthy/myApps/viztral && git add . && git commit -m "Deploy latest updates" && git push origin main
⚠️
CRITICAL WARNING FOR NEW ENGINEERS
NEVER change nameservers on GoDaddy back to GoDaddy Defaults. Doing so will break the DNS records configured in AWS Route 53 and take down the web application app.viztral.ai instantly. If you need to make any DNS changes, you must do so inside the **AWS Route 53 Console** under the hosted zone for viztral.ai.
